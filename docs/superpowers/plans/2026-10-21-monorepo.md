# Recipe Community Monorepo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consolidate the website and current mobile source in recipe-community without breaking either application or GitHub Pages deployment.

**Architecture:** Root npm workspaces own installation and orchestration; apps/web and apps/mobile own their framework and application code. Root Cloudflare configuration and dist/pages preserve the deployed project's existing build contract. No shared application package is introduced.

**Tech Stack:** npm workspaces, React 19.2.6 (web), React 19.3.0 (mobile), Vinext/Vite, Expo 58, React Native 0.88, Cloudflare Pages/D1/R2.

**Spec:** docs/superpowers/specs/2026-10-21-monorepo-design.md

## Global Constraints
- Use npm workspaces with apps/web and apps/mobile.
- Preserve website Git history and existing product behavior.
- The original recipe-mobile checkout remains as a backup; do not delete it during migration.
- Keep each application's existing React, TypeScript and framework versions.
- Keep npm run build:pages and root dist/pages compatible with Cloudflare Git integration.
- Never add account_id to the Pages configuration.
- Do not run remote migrations or modify production data.
- Exclude local credentials, databases, generated native folders and build artifacts from Git.

## Review Focus
- Fresh clone with no application-local node_modules: resolve framework executables through installed package locations.
- Two React versions: each application must resolve its own version, including mobile bundles.
- Cloudflare running at repository root: validate root configuration and private Worker packaging.
- Local CLI invoked through workspace scripts: keep cwd, migration configuration and persistence paths explicit.
- Mobile source newer than its Git HEAD: import current files, not only committed mobile files.

### Task 1: Establish the two-workspace repository
**Files:** root package.json, package-lock.json, .gitignore, .npmrc; apps/web/**; apps/mobile/**.
**Interfaces:** Consumes the existing website tracked tree and current mobile source. Produces npm workspaces named @recipe/web and @recipe/mobile.

- [ ] Record clean website status and mobile source manifest; inspect ancestor AGENTS.md and preserve local state outside the tracked migration.
- [ ] Move website application source/configuration/scripts/tests to apps/web using Git-aware moves. Leave root deployment configuration and documentation history in place.
- [ ] Copy mobile source/assets/configuration/tests/AGENTS.md, excluding nested .git, dependencies, generated native folders, environment secrets and output directories. Compare imported source files against the original checkout.
- [ ] Create a private root package declaring workspaces ["apps/web", "apps/mobile"], existing Node >=22.13.0 requirement and miniflare/sharp override. Name child workspaces @recipe/web and @recipe/mobile while preserving their dependency versions.
- [ ] Define root dev (web), dev:web, dev:mobile, android, ios, build (web), build:web, build:pages, preview:pages, deploy:pages, test, lint, typecheck and install:ci commands. Aggregate validation commands run both workspaces; install:ci runs root npm ci.
- [ ] Generate a single root lockfile, remove child lockfiles and run npm ci from the repository root. Confirm npm ls reports both workspaces; resolve React from each app with createRequire and assert web=19.2.6 and mobile=19.3.0.
- [ ] Review git diff --stat and git status --short; confirm original mobile checkout and generated APK remain untouched. Commit the workspace layout when dependency installation succeeds.

### Task 2: Adapt web tools and deployment paths

### Task 3: Verify mobile resolution and document use
**Files:** apps/mobile/metro.config.js only if required by official Expo guidance; root README.md; apps/web/README.md; apps/mobile/README.md; implementation plan progress.
**Interfaces:** Consumes both workspaces and root lockfile. Produces a documented, verified monorepo.

- [ ] Read Expo 58 documentation and official monorepo guide before any Metro API changes. Prefer Expo automatic monorepo support; introduce custom resolver settings only if demonstrated necessary.
- [ ] Run npm test, npm run lint and npm run typecheck at root. Require successful checks in both workspaces.
- [ ] Run npm run export:all --workspace @recipe/mobile. Require Android, iOS and web exports to succeed from apps/mobile using workspace dependencies.
- [ ] Document root npm ci; npm run dev:web; npm run dev:mobile; npm run android; root Pages build/preview commands; per-app environment configuration and production API URL. Replace outdated absolute project paths and obsolete deployment claims in application READMEs.
- [ ] Review staged paths and scan for accidentally imported credentials, local databases, APKs, native build output and nested Git metadata. Compare mobile source manifest again to prove current source was preserved.
- [ ] Perform final git diff --check, root validation and artifact inspection. Report exact results and any native UI testing limitations. Commit completed migration; GitHub publication must preserve Git-triggered Pages deployment and must not be claimed successful without observing the remote result.

## Self-review
The three tasks cover layout, source preservation, dependency isolation, CLI paths, Pages compatibility, mobile export and documentation. No product features, dependency upgrades, remote migrations or deletion of the original mobile checkout are included. Native UI testing remains subject to computer-control availability; successful bundle export is not described as native UI acceptance.
